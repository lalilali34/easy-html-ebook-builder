# pass7 · 正文成文

## 本轮任务

把 `analysis.json` 的结构化分析写成一篇连续叙述的正文（`article.md`），供下游 HTML 渲染与读者阅读。`article.md` 只呈现原文内容，不加入分析字段、推断、例子或疑问。

## 输入字段

- `skeleton`：pass1 的 7 大块（b1–b7），提供全文论证主线。
- `blocks[]`：29 个子块的 `summary`、`key_points`、`author_says[].text`（以及 `function` 帮助判断叙述角色）。
- `relations[]`：块间关系，用来理解论证顺序与衔接。
- `author_says[].quote` 是原文引用，仅供核对；正文**不得逐字复述 quote**，必须转述。

## 输出字段

一篇纯 Markdown 的连续叙述文（`article.md` 的内容），不输出 JSON。结构要求：

1. 按 b1–b7 的顺序分节，每节用 `##` 或 `###` 小标题。
2. 小标题必须是内容性的（例如「什么是资产阶级法权」「按劳分配中的形式平等」「毛泽东晚年的关注」），**禁止**用「定义」「主张」「推论」「理由」「例子」「反驳」「结论」这类功能名做标题。
3. 每节 1–3 段连续叙述，不大量使用列表；如果必须用列表，最多 1 个列表、不超过 5 项。
4. 段落之间自然过渡，不要靠「首先/其次/最后」这类机械连接词堆砌。
5. 篇幅由你根据内容密度自行判断，不设固定字数；不要写成摘要，也不要全文照搬。

## 语言要求

- 把 ASR 错字规范化为可读词（等家交换→等价交换、权力原则→权利原则、隔达钢领批判→哥达纲领批判、资计生产阶级性→刺激生产积极性等），但不要改变原意。
- 不出现「目的」「依据」「依赖」「作者说」「我推断」「我的例子」「我的疑问」「子块」「时间范围」这些分析字段名。
- 可以自然使用「作者认为」「马克思指出」「文章提到」这类叙述。
- 不要逐字复述 `author_says` 的 `quote`，要用转述。
- 不要加入自己的推断、例子或疑问；`article.md` 只呈现原文内容，推断留给 `analysis.json`。

## 禁止事项

- 禁止输出 HTML 或任何特殊标记（`<div>`、`[[...]]`、`{{...}}` 等）。
- 禁止使用「定义/主张/推论/理由/例子/反驳/结论」作为小标题。
- 禁止出现「整理自」「本文由分析生成」「本文将……」这类元信息。
- 禁止输出 JSON 或代码围栏。
