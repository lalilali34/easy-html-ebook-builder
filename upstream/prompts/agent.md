# 分析协议（agent.md）

本文件是 subtitle-to-structure 的分析协议，不是渲染提示词。它约束任何执行 pass1–pass6 的模型（或 dry-run 占位实现）如何产出分析结果。

## 1. 输出纪律

1. **只输出 JSON**，不输出解释、前言、markdown 代码围栏、注释。
2. 输出必须符合 `schema/analysis.schema.json`。字段名、层级、枚举值逐字照抄 schema。
3. 一轮只做该轮任务。**禁止提前填后续 pass 的字段**，也禁止把 pass1 的结论直接当最终 analysis.json 提交。
4. 不确定就留空数组或写 `边界可疑`，**不得编造**。

## 2. 功能标签（封闭集合，不可自造）

```
定义 | 提出问题 | 主张 | 理由 | 证明步骤 | 例子 | 反驳 | 推论 | 过渡 | 结论
```

一个功能块只能挂一个标签。相邻段落功能相同才合并为一个块；功能不同不得为了凑块数而合并。

## 3. 作者说的话必须可溯源

- `author_says` 是「作者说了什么」，不是「我理解成了什么」。
- 每条至少带 `quote`（原文引用，逐字）或 `timestamp`（该内容在字幕中的起点秒数）之一；能两者都给时都给。
- 转述可以写进 `text`，但必须能被 `quote` 或 `timestamp` 指回原文。
- `quote` 必须从输入字幕里逐字摘，不改写、不补字、不翻译。

## 4. 推断、例子、疑问分字段

| 字段 | 装什么 | 绝不能装 |
| --- | --- | --- |
| `author_says` | 作者的原始主张、定义、例子 | 我的推断、我的例子、我的疑问 |
| `my_inferences` | 我从结构里读出来、但作者没明说的东西 | 作者的原话 |
| `my_examples` | 我自己补充的例子 | 作者的例子 |
| `my_questions` | 我读完后仍然存疑的地方 | 作者已回答的内容 |

四类内容混在一起，视为本轮失败，必须重跑。

## 5. 依赖与置信度

- `depends_on` 只填**已存在的功能块 id**（形如 `b1`）。
- 填不出、或者依赖指向字幕里没有的隐含前提时，写字符串 `边界可疑`，**不得编造一个不存在的 id**。
- `confidence` 只能是 `high` / `medium` / `low`：
  - high：作者明确说出、且能在原文找到直接对应；
  - medium：需要结合上下文才能成立的推论；
  - low：结构位置可疑、或作者说得不充分。

## 6. 先还原，再理解

1. 先回答：作者在这段想解决什么问题、凭什么、结论是什么。
2. 再回答：我自己的推断、例子、疑问是什么。
3. 顺序不得颠倒。任何 `my_*` 字段的内容都不能反过来被写成 `author_says`。

## 7. 轮次边界

| 轮次 | 只允许产出 | 禁止 |
| --- | --- | --- |
| pass1 | core_problem / core_conclusion / 大块结构 | 细节、引用、推断 |
| pass2 | 逐段功能标签、合并后的功能块 | 内容细节 |
| pass3 | relations | 任何内容字段 |
| pass4 | purpose / basis / depends_on / key_points | 作者原话、推断 |
| pass5 | 先 author_says，确认后 my_* | 把推断混入作者说 |
| pass6 | recap（一句话、主要步骤、三问） | 新增分析内容 |

## 8. 失败处理

- 某一轮输出的 JSON 非法、或字段越界（未知功能标签、非法关系类型、依赖指向不存在块）：**只重跑该轮**，前面的轮次结果保留在磁盘上，不回滚整条流水线。
- 每轮结果必须落盘，便于定位到具体 pass。

> pass7 及之后的成文/术语/补例子轮次不受「只输出 JSON」约束，按各自 passN prompt 的输出格式执行。
