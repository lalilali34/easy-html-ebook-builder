# pass7s · 补充例子

## 本轮任务

在 `article.md` 的基础上新增补充例子，产出 `article_with_examples.md`。`article.md` 本身保持不变（不覆盖）。

## 输入字段

- `article_md`：`article.md` 全文。
- `blocks[]`：`analysis.json` 全部子块的 `key_points` 与 `my_examples`。

## 例子分两类

- **原文例子**：保留在正文叙述里，不标记、不移动。
- **补充例子**：用 Markdown 引用块 + 「例：」开头，例如：

> 例：两个人同样加班，一个要养孩子、一个不用，实际生活水平不同。

不要写 HTML，不要加 class；下游会把引用块自动转成 `.supplement-example`。

补充例子可以带类型标记，下游会按类型给不同颜色左边框：

- `> 例[史]：` —— 历史事件 / 制度 / 年份
- `> 例[哲]：` —— 哲学家 + 著作或观点
- `> 例[经]：` —— 经济制度 / 机制 / 案例
- `> 例：` —— 没有明确类型的日常场景

## 例子来源（三类，鼓励混用）

1. **日常场景**：读者能直接想象的生活片段（两个人加班、宿舍热水、集体食堂）。
2. **学术例证**：具体人物 + 著作/观点，或历史事件/制度 + 年份地点。**必须给出人名或年份**；记不清就不写，绝不编造书名、页码、年份。
3. **`my_examples` 复用**：优先从 `analysis.json` 的 `my_examples` 改写，但不得逐字重复——换场景、换表述。

## 数量与位置

- 补充例子 **12–20 个**，宁可多不要少。
- **每个 `##` 小节至少 2 个**；论证密集的小节写 3 个。
- 同一个论证点允许从不同角度补两个（一个日常场景 + 一个学术例证），两种来源互补最好。
- 每条不超过 3 句，保持紧凑，不要展开成小故事。
- 优先插在该论证要点所在段落的下一行，不打断正文。

## 内容规则

1. 不以 `terms_draft.md` 的词条名作为例子主体（避免误触发悬浮框），必要时用泛指（「一个制度」「一种分配方式」）。
2. 只解释论证，不引入新观点、不评价作者对错。
3. 例子要是读者能想象的具体场景，不要抽象说理。
4. 学术例证记不清出处就降级为日常场景，不要硬编。

## 输出差异约束

`article_with_examples.md` 与 `article.md` 的差异只能是「新增引用块例子」：正文一个字都不能改、不能删、不能调序。
